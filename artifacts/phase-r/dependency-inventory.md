## Exclusive generated art

There are no standalone China portrait, map, music or sprite asset files in the runtime manifest. Portraits are SVG strings generated by `js/portraits.js`; terrain, settlements and fortresses are generated in `js/map-art.js`; battle buildings are drawn in `js/battle-scene.js`. All HTML script/style files are shared.

| File | Exclusive generated branch | Shared branches that must remain |
| --- | --- | --- |
| `js/portraits.js` | `han` palette, Han beard depth and hat | Arab, Rum, steppe, Caucasus, scars, age, prestige frames and general SVG infrastructure |
| `js/map-art.js` | `this.style='east'` is assigned only for `threeKingdoms`; early return of `culture='east'`; three palette alternatives; no-palm China condition; east wall ring/rotation; east houses/palace/keep coloring. Local `const east` in `drawSettlement` appears unused. | All land/coast/river/forest/mountain rendering, roads, sea paths, dynamic borders, Arab courtyard architecture, Roman settlement style and steppe settlement style |
| `js/battle-scene.js` | China `cfg.style==='east'` house tint | Current west tint and all shared tactical scene/UI rendering |

`east` is not a generic removal keyword. In `map-art.js` and `battle-scene.js`, the named style is proven China-only by the upstream assignment. Geographic east/الشرق, western-map eastward routes, Persian/Arab/Caucasus/steppe names and Khazar/tarkhan content are shared supported campaign content.

`WORLD_DATA.umayyad.hordes.turgesh.away='بلاد الصين'` is an off-map event narrative destination, not a playable Chinese campaign, faction, portrait or map reference. It does not activate `threeKingdoms` and should not be removed by a blanket string replacement.

## Documentation and tooling

- `README.md` presently advertises two scenarios and uses restoration of Han as a victory example; update these live instructions to the supported 715 campaign. Its shared save/migration wording needs to match R1's supported-versus-unsupported behavior.
- `docs/leader-research.md` discusses the 208 campaign; annotate the removed campaign as historical A–B coverage or narrow the active scope while preserving research history. `docs/phase-a.md` records eastern scenario test evidence: it is historical evidence, not a menu entry and should not be silently rewritten as a test that never happened.
- Phase A–F historical reports/artifacts and authoritatively extracted execution-package documents may legitimately contain China strings. They are not loaded by `index.html` and do not expose China in normal gameplay.
- `tools/phase-f-preview.cjs` has no Chinese-specific runtime dependency. It builds explicit runtime files, and the approved public preview must remain untouched. Its storage wrapper currently namespaces only `store.get`, `set`, `del`; any new R1 raw-storage helpers require local tooling compatibility checks before using a new build, without publishing R over F.
- No Chinese-specific references found in `index.html`, `manifest.json`, `icon.svg` or runtime CSS. Shared icon/font/PWA files remain.

## Required removal verification risks

1. Reject unsupported save envelopes before `normalizeState` or any `SCENARIOS[saved.scenario]` lookup. Menu and manual-slot previews previously assume valid metadata. Removing data before these guards risks startup failures and save loss.
2. Verify supported old saves whose generals use legacy names still bind after catalogue removal. Preserve the Umayyad array's exact hash above if no unrelated catalogue changes are intended.
3. Remove special unique unit lookups and aliases together; recruitment/AI uses `UNIQUE_OF[fid]` and `UNITS[type]`. Do not remove generic icons or traits simply because Chinese units use them.
4. Preserve the geographic dataset and Umayyad routes/66-city graph. Neither the word east nor Chinese catalogue size justifies removing atlas data or Khazar content.
5. Historic tests/screenshots must be explicitly mapped to replacement coverage; keep unsupported China fixtures only for save-rejection/protection tests. Current F publication tests point to a deliberately protected F build and are not R-publication acceptance.
